## 1. 한 문장 요약

**방문자는 5,000개를 넘어선 외계행성 목록 앞에서, 우리가 눈으로 보지 않고 '별빛의 흔들림'만으로 수천 개의 세계를 발견했다는 것을 깨닫는다.**

---

## 2. 동기 (Why)

Phase 1부터 4까지의 여정: 우리 태양계 행성들의 공전 → 중력 하나에서 케플러의 타원이 태어나는 N-체 → 시공간 자체가 휘어 빛이 꺾이는 블랙홀. 이 모든 것은 우리가 *직접 보거나 알고 있는* 우주였다.

Phase 5는 그 경계를 넘는다.

외계행성은 직접 볼 수 없다. 별 자체도 우리 눈에는 점으로 보이는데, 그 별 주위를 도는 행성이라니. 그러나 1995년, 인류는 처음으로 다른 별 주위의 행성을 발견했다 — 51 Pegasi b. 별빛이 미세하게 흔들리는 것을 보고, *보이지 않는 행성의 존재를 추론*했다. 보이지 않는 것을 추론으로 발견하는 방법 — 이것이 천문학에서 가장 아름다운 인식론이다.

2009년 케플러 우주망원경이 발사되면서 게임이 바뀌었다. 행성이 별 앞을 지나갈 때 별빛이 미세하게 어두워지는 현상(transit)을 우주에서 정밀 관측하기 시작했다. 4년 만에 수천 개. 2023년 기준 확인된 외계행성만 5,500+개. 우리 은하에 별 하나당 평균 한 개 이상의 행성이 있다는 추정.

**Phase 5는 이 발견의 역사를 데이터베이스로 만든다.** 5,000개의 점이 화면을 채울 때, 방문자는 숫자가 아니라 *5,000개의 세계*를 보게 된다. 각 점은 어떤 방법으로, 언제, 어떤 특성을 가진 행성이 발견되었는지를 담고 있다.

기술적으로 이 Phase는 세 개의 도약이다: (1) **첫 백엔드** (FastAPI + Python — Phase 6–8 Lightkurve/MAST 기반), (2) **첫 외부 과학 데이터** (NASA Exoplanet Archive), (3) **첫 D3.js 시각화** (3D GLSL 레이마처에서 2D 데이터 탐색으로의 전환).

## 3. 사용자 시나리오

**60초 시나리오**:

1. **(0~10s)** `/exoplanet` 로드. 검은 배경에 5,000+개의 점이 화면을 채우는 D3 산점도 — 각 점이 하나의 외계행성. x축은 공전 주기(일), y축은 행성 크기(지구 반경 대비), 색상은 발견 방법. *"이게 다 행성이야?"*

2. **(10~30s)** 발견 방법 필터를 `Transit`으로. 점들의 대부분이 사라지지 않는다 — 오히려 *4,000개 이상이 남는다*. Radial Velocity로 바꾸면 — 1,000여 개. *"왜 이렇게 차이가 나지?"* 케플러가 몇 해 만에 얼마나 많은 것을 바꿔놨는지가 색상 분포로 보인다.

3. **(30~50s)** 크기 필터 슬라이더로 지구 유사 행성(R < 1.5 R♁)만 남기기. 수백 개로 줄어드는 화면. 그 중 하비터블 존 추정 행성들에 강조 표시. 한 점을 클릭하면 — 이름, 발견 연도, 항성까지 거리, 공전 주기, 발견 망원경.

4. **(50~60s)** *그 한 순간*. **[발견 타임라인]** 뷰 — 연도별로 점이 하나씩 나타나는 D3 애니메이션. 1995~2008년: 느리게 쌓이는 점. 2009년 케플러 발사: **폭발**. 2018년 TESS: 또 한 번. *"케플러 하나가 이 모든 걸 찾았다."*

**기억에 남길 한 순간** (PRD의 영혼):
- *발견 타임라인 애니메이션에서 2009년 케플러 발사 직후 점이 폭발적으로 늘어나는 1초* — 한 망원경이 인류의 외계행성 지식을 통째로 바꿔놓은 순간.

**보조 순간**:
- *5,000+점 중 "지구 비슷한" 필터를 적용하면 극소수만 남는 1초* — 지구가 얼마나 특별한 조건인지.

## 4. 범위

### ✅ 포함

1. **FastAPI 백엔드 scaffold** — `backend/` 디렉토리, Python 3.11, FastAPI, CORS 미들웨어. Railway 배포. `/api/planets` (목록+필터), `/api/planets/{name}` (상세), `/api/planets/stats` (집계). (5-1)

2. **NASA Exoplanet Archive 연동** — 공개 TAP REST API → httpx async 클라이언트 → Pandas DataFrame → JSON 직렬화. 서버 시작 시 전체 데이터 메모리 캐시 (데이터 변동 드묾). (5-1)

3. **프론트엔드 API 클라이언트** — `frontend/src/lib/api/exoplanet.ts`. fetch wrapper + 타입 정의. (5-1)

4. **ExoplanetPage 데이터베이스 테이블** — 검색(이름/항성)/필터(발견 방법, 크기 범위, 발견 연도)/정렬. 페이지네이션 또는 가상 스크롤. (5-2)

5. **D3.js 산점도** — x: 공전 주기(log scale), y: 행성 크기(R♁). 색: 발견 방법. 클릭 → 상세 패널. zoom/pan. (5-2)

6. **발견 타임라인 D3 애니메이션** — 연도별 점 누적. 케플러(2009)/TESS(2018) 발사 마커. (5-3)

7. **모바일 대응 + Lighthouse** — 테이블 반응형, 산점도 터치 지원, 번들 청크 분리 확인. (5-3)

### ❌ 제외

- **광도곡선 분석** (Kepler/TESS raw data + Lightkurve) — Phase 6
- **BLS 알고리즘** — Phase 7
- **미발견 행성 탐색 (MAST)** — Phase 8
- **3D 행성계 시각화** (Phase 2 태양계 스타일) — 과잉, 다른 씬과 충돌
- **사용자 인증 / 즐겨찾기** — YAGNI
- **실시간 데이터 갱신** (WebSocket) — 정적 캐시로 충분
- **Plotly.js / Recharts** — D3.js로 충분

## 5. 성공 기준

### 정성적

- *타임라인 애니메이션에서 케플러 발사 순간 점이 폭발하는 것*이 충격을 준다
- *"지구 비슷한 행성"으로 필터할 때의 고독함*이 느껴진다 ("이게 전부야?")
- 5,000+개의 데이터가 버벅거림 없이 탐색된다

### 정량적

- **로딩**: 백엔드 최초 응답 < 2s (캐시 이후 < 200ms)
- **산점도**: 5,000+ 점 렌더링 60fps
- **백엔드 `/api/planets`**: 캐시 적중 시 < 200ms
- **Lighthouse Performance 85+** (`/exoplanet`)

## 6. 비기능 요구사항

- **백엔드 독립 배포**: Railway. Vercel(프론트) + Railway(백엔드) 분리.
- **캐싱**: 서버 시작 시 NASA Archive 전체 데이터 메모리 캐시. 재시작 시 갱신. 별도 Redis 불필요(YAGNI).
- **CORS**: FastAPI CORS middleware — Vercel 프로덕션 도메인 + localhost:5173 개발 허용.
- **결측값 처리**: NASA Archive 필드는 nullable. Pydantic `Optional` 필드 + 프론트 null-safe 렌더.
- **번들**: D3 v7 추가(~500KB min). Vite manualChunks로 `vendor-d3` 분리. 기존 `vendor-three` 패턴 동일.
- **접근성**: 테이블 `aria-sort`, 필터 `<label>` 명시, 산점도 대체 요약 텍스트.

## 7. 천문학 — Phase 5에서 배우는 것

| 개념 | 비유 |
|------|------|
| Transit 방법 | 가로등 앞을 모기가 지나가면 빛이 살짝 어두워진다. 그 어두워지는 양(행성 크기)과 주기(공전 주기)로 행성을 안다. 케플러는 이걸 4년간 15만 개 별에 대해 했다 |
| Radial Velocity | 행성이 별을 잡아당기면 별도 미세하게 흔들린다. 그 흔들림의 도플러 효과(별빛 적청편이)로 행성의 질량을 안다. 1995년 51 Peg b 발견이 이 방법 |
| 하비터블 존 | 행성에서 물이 액체 상태일 수 있는 온도 범위. 별에서 너무 가까우면 증발, 너무 멀면 얼음. 지구는 그 좁은 골디락스 존에 있다 |
| 케플러 망원경 | 4년간 우주에서 15만 개 별을 지속 관측. 4,000여 확정 행성 발견. 총 비용 $600M — 행성 한 개당 $150,000 |
| Transit bias | Transit 방법은 "별에 가깝고 크고 관측자 시선과 잘 정렬된" 행성에 유리. 그래서 5,000개 중 대부분이 뜨겁고 거대한 "Hot Jupiter". 지구 같은 행성은 찾기 훨씬 어렵다 |
