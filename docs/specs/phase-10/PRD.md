# Phase 10 PRD — Skyward (온 하늘)

> *작성일: 2026-07-18*
> *상태: Draft → sub-10-1 진입 시 Confirmed*
> *이전 인계: `docs/phase-handoffs/phase-9B-to-9C.md` (TESS를 대안 트랙으로 명시)*

> 🛰️ 트랙 "모두의 하늘"의 **넷째 악장**. 9-A(판별기)·9-B(Kepler 개척지)에 이어,
> 이제 **사냥터를 Kepler 한 구멍에서 온 하늘로 넓힌다.** Kepler는 하늘의 0.25%
> (백조-거문고 한 패치)를 4년간 *깊게* 응시했다. TESS는 온 하늘(~85%)을 훑는다
> — 대신 각 구역을 27일씩 *얕게*. 깊은 눈에서 넓은 눈으로.

---

## 1. 한 문장 요약

**Kepler 한 구역에서만 사냥하던 개척지를 TESS의 온 하늘로 넓히되 — 넓은 눈은 얕게 본다는 사실(짧은 baseline → 무뎌진 판별)을 숨기지 않고, 진짜 사냥터로 가는 발견 가능한 입구(개척지 허브)를 처음으로 낸다.**

---

## 2. 동기 (Why)

9-B는 아무도 기록하지 않은 **Kepler** 별을 실제로 사냥했다. 정직한 사냥터를 지었고, 대부분 빈손이었으며, 그 빈손조차 결과였다. 그러나 Kepler가 본 하늘은 **딱 한 구멍**이다 — 백조자리와 거문고자리 사이 하늘의 0.25%를, 2009~2013 동안 꼼짝 않고 응시했다. 깊지만 좁다.

**그 너머 온 하늘은?** 2018년부터 TESS가 거의 전천(~85%)을 훑고 있다. 대신 한 구역(sector)을 27일씩만 본다. 넓지만 얕다. Kepler가 *한 우물을 깊게 판 눈*이라면, TESS는 *온 들판을 훑는 눈*이다. 두 눈은 상보적이다 — Kepler는 장주기에 강하고, TESS는 밝은 별·단주기에 강하다.

9-B의 사냥터를 이 온 하늘로 넓힌다. 그런데 지금 진짜 사냥터(`/hunt/frontier`)는 교육 데모(`/hunt`) 안의 링크 하나로만 도달한다 — **데모 밑에 파묻혀 있다.** TESS를 더 깊이 넣으면 두 겹 파묻힌다. 그래서 이 Phase는 사냥터를 넓히는 김에, **진짜 사냥터로 가는 발견 가능한 입구(개척지 허브)를 처음으로 짓는다** — 로드맵 nav와는 섞지 않은 채(분리 원칙 유지).

> Phase 9-B가 *"아무도 안 간 (Kepler) 하늘로 가자"* 였다면,
> **Phase 10은 "이제 온 하늘로 가자 — 대신 넓은 눈이 얕게 본다는 것까지 정직하게."**

---

## 3. 정직한 못 4 — 넓은 하늘은 얕게 본다

이 트랙은 못 1(목표는 "확정"이 아니라 "신뢰할 만한 후보")·못 2(방법은 NASA와 같아 믿을 수 있다)·못 3(사냥터도 정직해야 한다) 위에 섰다. Phase 10은 **넷째 못**을 박는다.

### 못 4 — 판별의 한계도 정직해야 한다

> 🌌 **TESS의 27일 baseline은 Kepler의 4년보다 훨씬 짧다. 우리 4관문은 여러 transit을 겹쳐 봐야 힘을 쓴다 — odd/even 비교는 홀·짝 식이 각각 있어야 하고, secondary는 긴 관측일수록 잘 잡힌다. TESS 단일 sector에선 transit이 2~3개뿐일 수 있고, 장주기 행성은 아예 창 안에 안 들어온다.**
> 즉 **TESS 개척지는 빈손이 더 흔하고, 우리 판별기의 칼날이 더 무디다.** 이걸 숨기면 못 2(방법의 정직)를 배신한다.

### 정직한 대응 — 겸손을 계량한다

낭만을 팔지 않는 건 9-B와 같다. 여기에 더해:

- **관측량을 노출한다** — 리포트에 baseline(관측 일수)·sector 수를 표시. 짧으면 짧다고 말한다.
- **짧은 관측의 strong은 더 겸손하게** — baseline이 임계 미만이면 `strong`도 *"잠정 strong (짧은 관측 — 추가 sector 필요)"* 로 한 단계 낮춰 어법. 확신을 관측량에 비례시킨다.
- **못 3은 그대로** — TESS 진짜 사냥 = **TOI에 항목이 없는 TIC**. recorded-gate가 TOI 멤버십으로 기계적 보장.

> **넓은 하늘의 진실: 더 많이 훑지만 더 얕게 본다. 빈손은 더 흔하고, 판별은 더 조심스럽다. 그 조심스러움을 계량해 보여주는 것이 못 4다.**

## 4. 사용자 시나리오

### 주요 경로 — 발견 가능한 입구에서 온 하늘로

1. **개척지 허브 진입** — 교육 데모를 거치지 않고 도달하는 **발견 가능한 입구**. 진짜 사냥터의 첫 집. (지금은 데모 안 링크 하나뿐 — 이것을 승격.)

2. **두 개척지 중 선택**:
   - *Kepler 개척지 (깊은 응시)* — 9-B 그대로. 하늘의 한 구역, 4년 baseline.
   - *TESS 개척지 (온 하늘)* — 신규. 거의 전천, 27일 baseline.

3. **TESS 사냥** (선택 시):
   - *무작위 미기록 TIC* 버튼 → TOI에 없는 TESS 관측 별을 하나 뽑는다. (또는 자유 입력.)
   - **TOI 대조 먼저** — 있으면 *"이미 기록된 천체"*(사냥 대상 아님), 없으면 **미기록 확정.**
   - LC(TESS) → BLS → 4관문 판별 (9-A 엔진 그대로) → trust 분기.
   - **관측량 노출** — baseline·sector 수를 결과에 표시. 짧으면 strong도 "잠정".

4. **미션별 정직 집계** — "Kepler N번 / TESS M번, 후보 K" — 미션을 섞지 않고 각각 정직하게.

### 기억에 남길 한 순간

> 파묻힌 링크가 아니라 제대로 된 입구로 개척지에 들어서고, "Kepler(깊게)와 TESS(넓게)" 두 하늘 앞에 서는 순간. 그리고 TESS 별을 처음 열었을 때 — *"아, 넓게 보는 대신 얕게 보는구나. 이 짧은 관측으론 확신을 덜 줘야 하는구나."* 판별기의 겸손을 눈으로 보는 순간.

---

## 5. 범위

### ✅ 포함

1. **개척지 허브 (발견 가능한 입구)** — 진짜 사냥터의 첫 집. Kepler/TESS 개척지 선택. **`phases.ts`에 넣지 않는다** (nav 로드맵과 분리 — 별도 nav 요소로 발견 가능하게). (10-1 or 10-3)

2. **TESS 사냥 백엔드** — TIC 번호로 TESS LC fetch(`mission="TESS"`), TOI 카탈로그 기반 recorded-gate(`is_recorded`의 TESS판), 사전 검증된 미기록 TIC 씨드 풀. 판별은 `vetting.vet` 그대로. (10-1)

3. **관측량 노출 + 겸손 어법 (못 4)** — 결과에 baseline·sector 수 표시. 임계 미만 baseline이면 strong → "잠정 strong" 강등. (10-2)

4. **TESS 결과 분기 UI** — 9-B `FrontierVerdict`/`HuntLog` 흐름을 미션 파라미터로 확장(공유 or 병렬). 미션별 정직 로그. (10-2)

5. **재사용** — `vetting.vet`(4관문+de-alias)·`FrontierHuntPage` 흐름·`DiscoveryActions`(discovery@2)를 **그대로**. Phase 10은 데이터 소스 + 사냥터 + 입구만 넓힌다. 새 판별 0.

### ❌ 제외 (다음으로)

- **사용자 계정 / 발견 저장소 / 커뮤니티** — 트랙의 다른 악장 9-C "모두의 발견".
- **다중 sector 정밀 stitch 최적화** — 기본 lightkurve stitch로 충분. detrending 고급화는 YAGNI.
- **TESS 2분 cadence 전용 파이프라인** — long cadence(FFI/QLP) 우선. 단주기 정밀은 향후.
- **Kepler × TESS 교차검증** — 같은 별을 두 미션으로 대조하는 건 별도 과제.
- **픽셀 수준 진단 (centroid)** — 4관문 이후 고급 단계, 미션 무관하게 미룸.

## 6. 성공 기준

### 정성적

- **개척지 허브가 발견 가능**하다 — 교육 데모를 거치지 않고 진짜 사냥터에 도달한다.
- Kepler(깊게)와 TESS(넓게)의 **상보성**이 UI에서 느껴진다.
- 짧은 baseline의 겸손 어법이 **잘난 척이 아니라 정직**으로 읽힌다 (못 4).

### 정량적

- **TESS 미기록 판정**: TOI에 있는 TIC 입력 → "이미 기록됨" / TOI에 없는 TIC → 사냥 진입. 라이브 검증.
- **관측량 노출**: 모든 TESS 결과에 baseline(일)·sector 수 표시. baseline < 임계 → strong이 "잠정 strong"으로 강등되는 것을 라이브로 확인.
- **미기록 TIC 추출**: 뽑힌 TIC가 (i) TESS LC 실존 (ii) TOI에 없음 — 둘 다 충족.
- **`npm run build` + `pytest` 통과**: 매 커밋.

---

## 7. 비기능 요구사항

- **판별은 9-A 그대로** — 새 판별 로직 0. Phase 10은 데이터 소스(TESS) + 사냥터(TIC/TOI) + 입구(허브) + 겸손 계량(못 4)만 추가.
- **미기록 판정은 로컬** — `toi_catalog.csv` 대조(새 외부 API 없음). 미기록 씨드의 "관측 데이터 존재" 확인만 빌드 타임 lightkurve 프로브.
- **정직성 UI 규칙 계승** — "확정" 단정 금지. 빈손은 결과. "발견" 단어는 strong+미기록에만. **추가**: 짧은 baseline strong은 "잠정"으로.
- **manualChunks 순서**: `@react-three` → `/three/` 절대 변경 금지.
- **분리 원칙**: 개척지 허브는 발견 가능하되 **로드맵 nav(`phases.ts`)와 섞지 않는다.** 진짜 사냥과 교육 데모의 경계는 유지.

## 8. 천문학 — Phase 10에서 배우는 것

| 개념 | 설명 |
|------|------|
| Kepler의 시야 | 하늘의 ~0.25%(백조-거문고 한 패치)를 4년간 응시. 깊지만 좁다 — 장주기 행성에 강하다. |
| TESS의 시야 | 거의 전천(~85%)을 sector로 나눠 훑는다. 각 sector 27일 — 넓지만 얕다. |
| Sector | TESS가 하늘을 나눈 관측 단위. 별마다 겹쳐 관측된 sector 수가 다르다(적도 근처 1개, 극 근처 수십 개). |
| baseline과 판별 | 관측 기간이 짧으면 transit 수가 적다 → odd/even·secondary 판별이 약해지고 장주기는 놓친다. **관측량 = 확신의 상한.** |
| TIC / TOI | TIC = TESS Input Catalog(관측 대상 별). TOI = TESS Object of Interest(후보). KIC/KOI의 TESS판. |
| 검출 편향의 상보성 | TESS는 밝은 별·단주기에, Kepler는 어두운 별·장주기에 강하다. 두 서베이는 서로의 사각을 메운다. |
