## 1. 한 문장 요약

**방문자는 실제 케플러 위성이 측정한 별빛의 파형을 보고, 보이지 않는 행성이 별 앞을 지나갈 때 빛이 정확히 얼마나 어두워지는지 — 그 희미한 1% 신호 하나에 수천 개의 세계가 숨어 있었음을 깨닫는다.**

---

## 2. 동기 (Why)

Phase 5는 *발견된 행성의 목록*을 보여줬다. 방문자는 5,000+개의 점이 화면을 채우는 것을 보고 케플러가 2009년에 폭발적으로 많은 것을 발견했다는 걸 느꼈다.

그런데 *어떻게?* 케플러는 4년 동안 15만 개의 별을 들여다보며 무엇을 기록했는가?

**바로 별빛이다.**

케플러가 측정한 것은 초당 별빛의 밝기 변화다 — 작게는 0.01%의 밝기 변화까지. 행성이 별 앞을 지나가면 별의 단면적 일부를 가리고, 그 순간 별빛이 미세하게 어두워진다. 이 어두워짐의 깊이(행성 크기), 주기(공전 주기), 모양(대기 유무)을 읽어 행성을 안다.

이것이 **광도곡선 (Light Curve)** — 시간에 따른 별빛의 흐름. 별이 부르는 노래.

Phase 6는 그 노래를 직접 본다.

- Phase 5 외계행성 목록에서 행성 하나를 선택
- 케플러/TESS가 그 별을 실제로 관측한 데이터를 불러옴
- D3로 광도곡선을 그림 — "여기, 이 딥(dip)이 바로 그 행성이야"
- 위상 접기 (phase folding): 주기로 데이터를 접으면 잡음이 사라지고 transit이 명확해짐

**Phase 5가 지도였다면, Phase 6는 원본 녹음 파일이다.**

기술적으로:
- (1) **Lightkurve** — NASA 공식 Python 라이브러리, MAST 접근 표준
- (2) **FastAPI 백엔드 재사용** — `/api/lightcurve/{name}` 엔드포인트 추가
- (3) **D3 시계열 차트** — Phase 5 D3 패턴(useRef + useEffect + ResizeObserver) 계승

## 3. 사용자 시나리오

**60초 시나리오**:

1. **(0~5s)** `/data` 로드. 상단에 검색창: "별 이름 또는 행성 이름을 입력하세요". 기본값: `Kepler-452 b` (지구와 가장 비슷한 행성 중 하나).

2. **(5~20s)** 검색 → 로딩 → D3 광도곡선 등장. x축 = 시간(일), y축 = 상대 밝기(1.0 = 정상). 파형이 대부분 1.0 근처에서 흔들리다가, 일정 간격으로 딥(dip)이 파인다. *"저 파인 곳이 행성이 별 앞을 지나간 순간이다."*

3. **(20~40s)** "Phase Fold" 버튼. 공전 주기(예: 384일)로 데이터를 접으면 — 잡음은 평균화되고 transit 딥이 선명하게 부각된다. 완벽한 U자 모양. *"이게 행성의 '지문'이다."*

4. **(40~60s)** Transit 딥 위에 자동 마커: 깊이(Transit Depth) = X%, → 행성 반경 = Y R♁. 마커를 클릭하면 Phase 5 PlanetDetail 패널이 열린다. *"숫자가 아니라 이 딥에서 행성이 나왔다."*

**기억에 남길 한 순간** (PRD의 영혼):
- *Phase Fold 버튼을 누를 때 흩어진 잡음이 한 줄의 선명한 U자로 수렴하는 0.5초* — 수백 번의 transit을 하나로 쌓아 신호를 끌어내는 순간.

## 4. 범위

### ✅ 포함

1. **Lightkurve 백엔드 통합** — `backend/` 에 Lightkurve 설치 + `/api/lightcurve/{name}` 엔드포인트. MAST에서 Kepler/TESS 광도곡선 다운로드 + 전처리 (SAP_FLUX 또는 PDCSAP_FLUX, NaN 제거, 정규화). (6-1)

2. **광도곡선 캐시** — MAST 호출은 느림 (~5-10s 최초). 파일 기반 캐시 (`backend/cache/lc_{name}.json`). 재시작 후에도 유지. (6-1)

3. **DataPage 기본 뷰** — 검색창 + D3 시계열 광도곡선. x: 시간(BTJD days), y: 상대 밝기. 줌/팬. (6-2)

4. **Phase Folding 뷰** — 공전 주기로 데이터를 위상 접기. D3 Phase Diagram. transit 딥 자동 마커. (6-2)

5. **Transit 상세** — 딥 깊이, 지속시간, 추정 반경. Phase 5 PlanetDetail 재활용. (6-3)

6. **Planet 연동** — Phase 5 ExoplanetPage의 행성 클릭 → "광도곡선 보기" 버튼 → `/data?planet=Kepler-452+b`. (6-3)

### ❌ 제외

- **BLS (Box Least Squares) 알고리즘** — Phase 7. 주기 탐색 알고리즘.
- **미발견 행성 탐색** — Phase 8. 이 Phase는 "이미 알려진 행성의 광도곡선"만.
- **다중 별 비교** — 단일 별/행성 뷰에 집중. 복수 비교 UI는 YAGNI.
- **Lightkurve CBV (Cotrending Basis Vectors) 보정** — 기본 PDCSAP_FLUX로 충분.
- **자체 MAST 미러 / S3 캐싱** — 파일 캐시로 충분. Redis/S3 YAGNI.
- **사용자 업로드** — 외부 `.fits` 파일 업로드 없음. MAST 한정.

## 5. 성공 기준

### 정성적

- *Phase Fold 버튼을 누를 때 U자 transit이 선명하게 나타나는 순간*이 인상에 남는다
- *"케플러가 이 신호 하나로 행성을 찾았구나"* 라는 실감이 온다
- Phase 5 행성 목록 → Phase 6 광도곡선 연동이 자연스럽다

### 정량적

- **광도곡선 로딩**: 최초 (MAST) < 15s, 캐시 후 < 500ms
- **D3 렌더링**: 50,000+ 데이터 포인트 버벅 없이 (decimation 또는 SVG path 최적화)
- **Lighthouse Performance**: `/data` 페이지 ≥ 85 (mobile)
- **Phase Folding**: 1,000+ 포인트 접기 계산 < 100ms (클라이언트 또는 서버)

## 6. 비기능 요구사항

- **백엔드 재사용**: Phase 5 FastAPI + 신규 라우터 추가. 별도 서비스 불필요.
- **MAST 속도 대응**: 캐시 미스 시 로딩 UI + 진행 상태 메시지 ("케플러 데이터 내려받는 중…").
- **데이터 크기**: Kepler 장기 관측 광도곡선 = ~65,000 포인트. JSON 전송 시 ~1MB. 데시메이션 또는 바이너리 고려.
- **CORS**: 기존 Phase 5 CORS 설정 그대로.
- **Lighthouse**: Phase 5와 동일한 자체 호스팅 폰트 + 코드 분할 패턴 유지.

## 7. 천문학 — Phase 6에서 배우는 것

| 개념 | 비유 |
|------|------|
| 광도곡선 | 별을 몇 달 동안 사진 찍어 밝기를 그래프로. 별이 쉬지 않고 부르는 노래. |
| Transit 딥 | 행성이 별 앞을 지나가면 빛이 살짝 줄어든다. 지구 크기 행성은 태양 밝기의 0.008% 감소. |
| SAP vs PDCSAP flux | SAP = 원시 광도. PDCSAP = 위성 자체 모션 보정. 우리는 PDCSAP 사용. |
| Phase Folding | 공전 주기 T로 시간 t를 `t mod T` 처리 → 같은 위상의 데이터가 겹침 → S/N 향상. |
| BTJD | Barycentric TESS Julian Date. MAST 시간 단위. JD 2,457,000 기준 offset. |
| 케플러 관측 시간 | 케플러는 2009~2013 동안 4년 연속 같은 별을 관측. Kepler 입력 등록 약 150,000개 별. |
