## 1. 한 문장 요약

**방문자는 뉴턴의 법칙 한 줄(`F = G·m₁·m₂ / r²`)에서 케플러의 궤도가 *저절로* 태어나는 것을 보고, 그 우주를 굴리는 *방법(적분기)* 이 우주의 운명을 가른다는 것을 깨닫는다.**

---

## 2. 동기 (Why)

Phase 2에서 우리는 케플러의 *결과* 를 손으로 그렸다 — 행성을 정해진 원궤도에 올려놓고 시간 슬라이더로 돌렸다. 궤도는 *우리가 그려준* 것이지, *스스로 생긴* 것이 아니었다.

케플러는 관측으로 **무엇** 을 알아냈다: 행성은 타원을 그리고, 공전 주기의 제곱은 궤도 반장축의 세제곱에 비례한다 (제3법칙). 그러나 *왜* 그런지는 답하지 못했다. 반세기 뒤 뉴턴이 **왜** 를 답했다 — 질량은 서로를 거리 제곱에 반비례해 끌어당긴다. 그 한 줄에서 케플러의 세 법칙이 *연역* 된다.

**Phase 3는 그 방향을 거꾸로 코드로 다시 쓴다.** 행성에게 궤도를 그려주지 않는다. 뉴턴의 법칙만 주고, *적분기로 시간을 굴려서*, 케플러의 타원이 **스스로 나타나는지** 본다. 코드가 중력을 "이해" 하는지를 2체 해석해로 검증하는 일 (sub-3-2) 이 이 Phase의 심장이다.

그리고 여기서 *컴퓨터가 왜 필요한가* 가 드러난다. 2체는 손으로 풀린다 (케플러). 그러나 **3체부터는 일반해가 없다** — 닫힌 수식으로 적을 수 없고, *수치 적분* 으로만 미래를 알 수 있다. 우주의 운동은, 세 몸만 모여도, *계산* 으로만 답하는 문제가 된다. *가장 작은 단위(비트)로 가장 큰 질문(우주가 어떻게 움직이는가)에 다가가는* 이 프로젝트의 영혼이 여기서 가장 선명하다.

마지막으로 — *방법* 의 진실. 같은 뉴턴 법칙도, 순진한 1차 적분(Euler)으로 굴리면 에너지가 새어 궤도가 나선으로 풀려 **우주가 깨진다**. 4차 룽게-쿠타(RK4)로 굴리면 궤도가 *닫힌다*. 같은 법칙, 다른 방법, 다른 우주. sub-2-7에서 *측정* 이 *"폴리곤을 줄이자"* 는 가정을 이겼듯, Phase 3에서는 *방법(적분기)* 이 *"적분이야 다 비슷하겠지"* 라는 가정을 이긴다. 불칸의 거울이다.

기술적으로는 — `lib/physics/` 의 **순수 함수 + TDD** 첫 무대 (해석해로 검증 가능하니 TDD가 *자연스러운* 영역), Phase 2의 *useFrame-derived 무리렌더* 패러다임을 *상태가 실제로 변하는* N-body 적분에 적용하는 첫 시도, Scene/카메라/시간 컨트롤 자산 재사용 검증.

## 3. 사용자 시나리오

**60초 시나리오**:

1. **(0~10s)** `/gravity` 로드. 기본 프리셋 **"우리 태양계 (N-body)"** 가 돌고 있다 — Phase 2와 비슷해 보이지만, 이제 모든 천체가 *서로* 를 끌어당긴다. 각 천체 뒤로 *궤적(trail)* 이 페이드아웃되며 그려진다. *Phase 2를 중력 버전으로 재방문* 하는 첫인상.
2. **(10~25s)** 프리셋을 **"2체: 태양-지구"** 로. 화면에 *깨끗한 타원 하나* 가 궤적으로 그려진다. 우리가 궤도를 그려준 게 아니다 — `F = G·m₁·m₂ / r²` 하나에서 케플러의 타원이 *태어난* 것이다. (이 타원의 보존량을 자동 테스트가 감시한다 — sub-3-2.)
3. **(25~40s)** 프리셋을 **"3체"** 로. 세 천체가 서로 얽혀 춤춘다. 화면의 **[섭동]** 슬라이더를 *머리카락 한 올만큼* 움직이면 — 같은 초기 구성인데 궤도가 *완전히 다른 운명* 으로 갈라진다. *결정론인데 예측 불가* — 카오스의 정수. (figure-8 프리셋은 published 초기조건이라 안 건드리면 영원히 8자를 그린다.)
4. **(40~60s)** *그 한 순간*. 안정한 2체를 띄운 채, 화면의 **[적분기: Euler | RK4]** 토글을 **Euler** 로 넘긴다 — 닫혀 있던 궤도가 몇 바퀴 만에 *나선으로 풀려 천체가 튕겨나간다*. 상단 **에너지 readout** 의 총 에너지 막대가 *솟구친다*. 다시 **RK4** 로 — 궤도가 *딱 닫히고* 에너지 막대가 *평평* 해진다. *"적분기를 잘못 고르면 우주가 깨진다."*

**기억에 남길 한 순간** (PRD의 영혼):
- *Euler를 켜는 순간 안정 궤도가 나선으로 풀려 우주가 깨지고, RK4로 되돌리면 궤도가 다시 닫히는 1초* — **방법의 진실**.

**보조 순간**:
- *3체에서 시작점을 머리카락 한 올 옮기면 운명이 갈리는 1초* — 카오스의 진실.

두 순간 모두 *같은 법칙, 다른 결과* 다. 하나는 *방법(적분기)* 이, 하나는 *초기조건(섭동)* 이 우주를 가른다. Phase 2의 *두 거짓말(거리·자전)* 이 *진실로 토글* 되는 무대였다면, Phase 3는 *하나의 진실(중력 법칙)* 이 *방법과 조건에 따라 다른 우주* 를 낳는 무대다.

## 4. 범위

### ✅ 포함 (7개)

1. **N-body 물리 코어** (`lib/physics/`) — *순수 함수 + TDD*. (a) 중력 가속도 `a_i = Σ G·m_j·(r_j−r_i)/(|r_j−r_i|²+ε²)^1.5` (softening ε), (b) **RK4 적분기**, (c) 비교·데모용 **Euler 적분기** (의도적 보존).
2. **2체 해석해 검증** — RK4가 *진짜로* 중력을 푸는지 보존량으로 자동 검증: 총 에너지·각운동량 보존, 케플러 제3법칙 `T² ∝ a³` 재현. *이 Phase의 안전망* (sub-3-2).
3. **프리셋** (`data/presets.ts` 단일 소스) — **2체**(태양-지구 타원), **3체**(figure-8 / 카오스), **쌍성계**, **우리 태양계(N-body)**. 태양계 프리셋은 `data/planets.ts` 의 real 값 재사용 (+ mass 필드 확장).
4. **궤적 (trails)** — 각 천체가 지나온 경로를 페이드아웃 라인으로. *케플러의 타원이 "그려지는" 것을 보는* 핵심 시각 장치.
5. **적분기 토글 [Euler | RK4] + 에너지/각운동량 readout** — **Phase의 영혼**. 방법 차이를 *수치* 가 아니라 *체감* 으로. readout이 *물리적으로 정상인지(에너지 보존)* 를 실시간으로 보여줌.
6. **시간 컨트롤 (Phase 2 재사용) + 물리 타임스텝 ↔ 시각 속도 *분리***. 시각 속도(0.1×~10,000×)를 올려도 적분 정확도는 *고정 dt* 로 보장 — 빠르게 = 프레임당 substep 더 많이. *물리 정확도와 시각 속도는 다른 축*.
7. **카오스 체험** — 3체 프리셋에서 초기조건 미세 섭동 슬라이더/버튼. 같은 구성, 갈라지는 운명.

### ❌ 제외

- **충돌 → 병합** — softening 으로 근접 시 `1/r²` *폭발만 방지*. 운동량 보존 머지는 범위 외 (YAGNI, 후속 미니).
- **상대론적 보정** (수성 근일점 세차 등) — *빛과 중력이 휘는 곳* 은 Phase 4 (블랙홀, GLSL).
- **사용자 임의 배치 에디터** (드래그로 천체 놓기) — 프리셋 + 섭동으로 충분. 필요해지면 별도 액션 (YAGNI).
- **적응형 타임스텝** (RKF45 등) — 고정 dt + substep으로 데모 정확도 충분. 정밀 적응 적분은 과잉.
- **물리적 크기 충돌 / 단면** — 모든 천체 *점질량* 가정.
- **3D 자유 궤도면 강제** — 프리셋은 *가독성 위해 평면 위주* 배치, 공간 자체는 3D (카메라 자유). 궤도 경사 무시.
- **N 대규모 (수백~)** — 직접합 O(N²) 가벼운 규모(수십)로 제한. Barnes-Hut 같은 tree code는 과잉.

## 5. 성공 기준

### 정성적
- *"Euler ↔ RK4 토글 순간"* 이 충격을 준다 (자체 테스트: 처음 본 친구 3명이 *"어, 깨졌다"* → *"아, 닫혔다"* 라고 반응하는가)
- *2체 타원이 `F = G·m₁·m₂ / r²` 만으로 태어난다* 는 게 느껴진다 — *우리가 궤도를 안 그렸다* 는 깨달음
- *3체 카오스의 예측 불가* 가 섭동 슬라이더로 체감된다
- *우리 태양계 프리셋* 이 Phase 2의 *재방문* 으로 느껴진다 (연속성)
- 길을 잃어도 **프리셋 재선택 한 번이면 깨끗한 초기조건으로** (Phase 2 reset 정신 계승)

### 정량적
- **2체 에너지 보존 (RK4)**: 권장 dt로 N바퀴 적분 후 *총 에너지 상대 오차 < 0.1%* (자동 테스트)
- **각운동량 보존 (RK4)**: *상대 오차 < 0.01%* (자동 테스트 — 중심력이라 정확히 보존되어야)
- **케플러 `T² ∝ a³` 재현**: 서로 다른 반장축 2체들의 `T²/a³` 가 *서로 1% 이내 일치* (자동 테스트)
- **Euler 발산 데모 보장**: 동일 초기조건·동일 스텝수에서 *Euler 에너지 오차 ≫ RK4* — 눈에 보이는 차이를 *회귀 테스트로 고정* (영혼이 우연이 아니게)
- **물리 정확도 = 시각 속도 독립**: 시각 속도 0.1×~10,000× 어디서든 *같은 초기조건 → 같은 궤도* (고정 dt substep, 회귀 테스트)
- **데스크톱 60fps** (N ≤ 수십 체 + trails + 카메라)
- **Lighthouse Performance 85+** (Phase 2 기준 유지 — `/gravity` 코드분할 청크 포함)

## 6. 비기능 요구사항

- **성능**: N-body 적분이 *메인스레드* 부담 → N 상한(수십) + substep 수 캡(시각 속도 폭증 시 프레임 드랍 방지). O(N²) 직접합은 이 규모에서 가벼움. trails는 ring-buffer로 메모리 고정.
- **정확성 (이 Phase의 비기능 1순위)**: *물리는 테스트가 정본*. `lib/physics` 순수 함수는 TDD. 보존량(에너지·각운동량·주기)이 *적분이 정상인지 vs 버그인지* 의 판별 기준 — 카오스라 궤도 발산 ≠ 버그이므로, 보존량으로 구분.
- **접근성**: 적분기 토글·프리셋은 키보드 조작 가능, *현재 적분기* 는 `aria-pressed`. 에너지 readout은 *색에만 의존하지 않음* (수치 병기).
- **모바일 대응**: 터치 카메라(Phase 2 `useIsTouchDevice` / OrbitControls 재사용), 컨트롤 패널 하단 고정. 모바일은 N·substep 상한을 데스크톱보다 보수적으로 (배터리·발열).
- **브라우저**: WebGL2 최신 Chrome / Safari / Firefox. Phase 2와 동일 fallback 정책.
