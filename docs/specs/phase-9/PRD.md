# Phase 9 PRD — Vetting

> *작성일: 2026-07-05*
> *상태: Draft → sub-9-1 진입 시 Confirmed*

> 🛰️ Phase 9는 9-Phase 로드맵(0~8) 종료 후 여는 **새 트랙 "모두의 하늘"의 첫 악장**이다.
> 로드맵이 "인류가 우주를 이해해온 순서"를 재현했다면, 이 트랙은 그 도구를
> *누구나 손에 쥐고 직접 새 행성을 찾을 수 있게* 만든다. Phase 8이 제외했던
> (§4) 위양성 자동 판별을 정면으로 다룬다.

---

## 1. 한 문장 요약

**BLS가 찾아낸 신호를, 우주 지식이 없는 사람도 "이게 왜 진짜 행성인지, 혹은 왜 허수아비인지" 스스로 판단할 수 있도록 — 원본 광도곡선만으로 자동 판별(vetting)하고 그 근거를 평이한 말로 설명한다.**

---

## 2. 동기 (Why)

Phase 8은 신호를 찾았다. 하지만 신호를 찾는 것과 그 신호가 **진짜 행성인지 아는 것**은 전혀 다른 일이다.

현재 Hunt의 유일한 검증은 *"NASA KOI 카탈로그에 있는가?"* 다. 문제는 이것이 **"카탈로그에 없음 = 새 발견"** 으로 읽힌다는 것이다. 그러나 카탈로그에 없는 신호의 절대다수는 행성이 아니다:

- **쌍성 (eclipsing binary)** — 두 별이 서로 가리며 만드는 깊은 식(食)
- **별 자체의 변광** — 흑점, 맥동
- **기기 노이즈 / 배경 오염**

> 판별 없이 울타리를 열면, 초심자가 고른 첫 별의 쌍성 신호가 "새 행성 발견!"으로 표시된다.
> 그것은 우리가 돕고 싶은 바로 그 사람을 속이는 일이다.

**그래서 판별(vetting)은 이 트랙의 심장이다.** 그리고 판별의 각 단계는 그 자체로 **가르침**이다 — "왜 이건 행성이 아닌가"를 설명하는 순간, 사용자는 천문학자가 신호를 의심하는 법을 배운다.

Phase 8이 *"찾을 수 있는가?"* 였다면, Phase 9는 **"찾은 것을 믿어도 되는가?"** 이다. 그리고 그 판단을 전문가의 특권이 아니라 **누구나의 능력**으로 만든다.

---

## 3. 정직한 못 두 개 — 처음에 박고 간다

이 트랙 전체가 신뢰를 근거로 서려면, 두 가지를 자기기만 없이 못 박아야 한다.

### 못 1 — 우리 목표는 "확정"이 아니라 "신뢰할 만한 후보"

> 🌌 **원본 아카이브 데이터만으로 새 행성을 *확정(confirm)* 하는 것은 불가능하다.**
> 확정에는 후속 관측(시선속도, 추가 측광)이 필요하며 이는 아카이브 밖의 일이다.
> **우리의 목표는 "확정 발견"이 아니라 "신뢰도 있는 새 *후보(candidate)* 를 우리 손으로 걸러내는 것"이다.**
> 이것은 축소가 아니다 — Planet Hunters 등 실제 시민 과학이 하는 바로 그 일이며, 정직하기에 오히려 더 강하다.

판별의 결과는 "행성이다/아니다"의 단언이 아니라 **신뢰도(trust)와 그 근거**다. 우리는 확신을 팔지 않는다. 우리는 **판단의 재료**를 준다.

### 못 2 — 방법은 NASA와 같다(그래서 믿을 수 있다). 우리 것은 "다시 짓고, 여는" 방식이다

> 🔭 **판별의 과학(홀짝·2차 식·모양·S/N)은 우리가 발명한 게 아니다.** NASA 케플러 파이프라인(Robovetter)·TESS·Planet Hunters가 쓰는 **표준 방법**이다. **이것은 약점이 아니라 신뢰의 근거다** — 표준을 쓰기에 우리 후보가 NASA와 같은 언어로 비교·검증 가능하다. 아무도 안 쓰는 "독창적 판별법"을 만들면 아무도 신뢰할 수 없다.

그렇다면 무엇이 우리 독자적인 것인가 — 세 가지, 그리고 셋 다 진짜 가치가 있다:

1. **직접 재구현 = 독립 검증.** 라이브러리의 "판별 버튼"을 누르는 게 아니라 BLS도 판별도 바닥부터 우리가 짠다. 같은 데이터를 독립 알고리즘으로 돌려 같은 결론에 도달하는 것 — 이것이 과학의 "독립 재현"이며 후보 신뢰도를 실제로 올린다. 우리가 도는 순간 그것은 **두 번째 눈**이다.
2. **아무도 안 한 조합.** *원본 망원경 데이터 + 완전한 판별 + 비전공자도 이해하는 설명* — 이 셋을 한 도구에 담은 것은 드물다. NASA 파이프라인은 전문가용 블랙박스, Planet Hunters는 판별의 논리를 가르치지 않는다.
3. **판별의 창(窓).** 망원경 옆에 유리창을 달아 **누구나 그 안에서 판단이 일어나는 과정을 지켜보게** 한다. 렌즈 깎는 법은 교과서에 있지만, "누구나 그 안을 들여다볼 수 있는 창"은 우리 것이다.

**한 문장으로: 방법은 NASA와 같아 믿을 수 있고, 그걸 우리 손으로 다시 짓고 누구나 이해하게 여는 방식이 우리 독자성이다.**

## 4. 사용자 시나리오

### 주요 경로 — 신호를 심문하다

1. **(Phase 8 흐름 그대로)** 타깃 선택 → BLS 실행 → 주기도그램 + 최우선 주기 검출.

2. **(신규)** BLS 결과 아래 **"판별 리포트(Vetting Report)"** 가 열린다. 신호가 네 개의 관문을 통과하는 과정이 **하나씩** 보인다:

   - 🔵 **홀짝 깊이** — *"홀수번째와 짝수번째 어두워짐의 깊이가 같습니다. 매번 같은 것이 지나갔다는 뜻 — 행성다움 ✓"* / 또는 *"깊이가 다릅니다. 서로 다른 두 별이 번갈아 가린 흔적일 수 있어요 — 쌍성 의심 ✗"*
   - 🔵 **2차 식** — *"행성 반대편에서 추가 어두워짐이 없습니다. 동반체가 스스로 빛나지 않는다는 뜻 — 행성다움 ✓"*
   - 🔵 **모양** — *"어두워짐의 바닥이 평평합니다(U자). 온전한 원반이 별 앞을 가로질렀어요 — 행성다움 ✓"* / *"바닥이 뾰족합니다(V자). 스치듯 지나간 쌍성일 수 있어요 ✗"*
   - 🔵 **크기와 선명도** — *"신호대잡음이 충분하고, 추정 반지름이 목성급입니다. 행성 범위 안 ✓"* / *"추정 반지름이 항성급입니다 — 행성이라기엔 너무 큽니다 ✗"*

3. **(종합)** 네 관문의 결과가 하나의 **신뢰도 요약**으로 모인다:
   - *"4개 검사 중 4개 통과 — 이 신호는 행성 후보로서 신뢰할 만합니다."*
   - *"4개 중 1개 통과 — 이 신호는 쌍성일 가능성이 높습니다. 행성 후보로 보고하지 않는 것을 권합니다."*

4. **(발견 기록 v2)** JSON 내보내기에 **판별 근거가 함께** 담긴다. "발견"이 이제 주장이 아니라 **증거를 동반한 기록**이 된다.

### 기억에 남길 한 순간

> 각 관문의 짧은 애니메이션과 함께 평이한 문장이 뜨는 순간.
> *"아, 천문학자들은 이렇게 신호를 의심하는구나. 나도 이제 볼 줄 안다."*

## 5. 범위

### ✅ 포함

1. **판별 엔진 (백엔드)** — 캐시된 광도곡선 + BLS 결과로부터 네 진단 지표 계산: odd/even 깊이비, secondary eclipse 깊이, transit 모양(V/U 지표), S/N 및 깊이→반지름 추정. `GET /api/hunt/vet/{kic}` (9-1)

2. **판별 리포트 (프론트)** — 각 관문을 순차 공개하는 `VettingReport` 컴포넌트. 관문별 통과/실패 + **평이한 설명 문장**. HuntPage 결과 흐름에 통합 (9-2)

3. **신뢰도 종합 + 발견 기록 v2** — 네 관문을 하나의 신뢰도 요약으로 합성. `lib/discovery.ts` 스키마를 `discovery@2`로 확장해 판별 근거 포함 (9-3)

4. **재사용** — Phase 8 `fetch_lc_by_kic` 캐시 + Phase 7 `run_bls` 결과 그대로 입력으로 사용. 판별은 이미 있는 광도곡선·주기 위에서 도는 순수 계산.

### ❌ 제외 (다음 악장으로)

- **울타리 열기 (임의 KIC/TIC 입력, TESS 편입)** — 트랙의 다음 Phase(9-B "울타리 열기"). 판별기가 진짜/가짜를 가릴 수 있게 된 *다음에* 사냥터를 넓힌다.
- **픽셀 수준 진단 (centroid shift, difference imaging)** — target pixel file 필요. 광도곡선만으로 하는 4관문 이후의 고급 단계.
- **사용자 계정 / 발견 저장소 / 커뮤니티** — 트랙의 마지막 악장(9-C "모두의 발견").
- **transit 물리 모델 정밀 피팅 (Mandel-Agol 등)** — 판별에는 근사 지표로 충분. 정밀 피팅은 YAGNI.

## 6. 성공 기준

### 정성적

- 우주 지식이 없는 사람이 리포트를 읽고 *"왜 이게 행성이 아닌지"* 를 자기 말로 설명할 수 있다.
- "발견"이 근거 없는 주장이 아니라 **증거를 동반한 판단**으로 느껴진다.
- 각 관문이 교육적이다 — 통과든 실패든 배움이 남는다.

### 정량적

- **알려진 확정 행성 (KIC 11446443)**: 4관문 모두 통과 (진짜 양성).
- **알려진 쌍성/위양성 타깃**: 최소 하나의 관문에서 명확히 실패 (진짜 음성). *→ 판별기가 실제로 구별하는지 라이브 검증.*
- **판별 계산**: 캐시된 LC + 주기 입력 시 < 1s.
- **`npm run build` + `pytest` 통과**: 매 커밋.
- **판별 로직은 TDD**: 지표 계산 함수는 합성 광도곡선(known 쌍성/행성 모사)으로 실패 테스트 먼저.

## 7. 비기능 요구사항

- **판별은 순수 계산** — 새 외부 API 없음. 입력은 캐시된 LC(`backend/cache/lc_*.json`)와 BLS 주기. 결정론적·테스트 가능.
- **검증 데이터**: 확정 행성 1 + 쌍성/위양성 1을 기준 타깃으로 고정 (성공 기준의 진짜 양성/음성 앵커).
- **백엔드 재사용**: Phase 8 `services/hunt.py`에 판별 함수 추가 또는 `services/vetting.py` 신설 — 실물 구조 보고 sub-9-1 Plan에서 확정.
- **정직성 UI 규칙**: 판별 결과 문구에 "확정/확인된 행성"이라는 단정 금지. 항상 "행성다움 / 후보로서 신뢰할 만함 / ~일 가능성" 어법.
- **manualChunks 순서**: `@react-three` → `/three/` 절대 변경 금지.

## 8. 천문학 — Phase 9에서 배우는 것

| 개념 | 설명 |
|------|------|
| Vetting (판별) | transit 신호가 진짜 행성인지 걸러내는 과정. NASA도 BLS/TCE 검출 후 반드시 거친다. 검출 ≠ 발견. |
| Eclipsing Binary (식쌍성) | 두 별이 서로를 가리며 만드는 깊은 식. 위양성의 최대 원인 — transit처럼 보이지만 행성이 아니다. |
| Odd/Even Test | 홀·짝 식의 깊이가 다르면, 실제 주기의 절반에 락온한 쌍성. 진짜 행성은 매번 동일. |
| Secondary Eclipse (2차 식) | 동반체가 별 뒤로 숨을 때의 미세한 감광. 존재하면 동반체가 발광체 = 별. 행성은 거의 없음. |
| Transit Shape (U vs V) | 평평한 바닥(U)은 온전한 원반 통과(행성적), 뾰족한 바닥(V)은 스치는 식(쌍성적). |
| 깊이 → 반지름 | 감광 깊이 ≈ (행성반지름/별반지름)². 추정 반지름이 항성급이면 행성이 아니다. |
| False Positive의 정직성 | 과학은 "찾았다"가 아니라 "아니라고 배제할 수 없다"로 나아간다. 판별은 배제의 기술이다. |
