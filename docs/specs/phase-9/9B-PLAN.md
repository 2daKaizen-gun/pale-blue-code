## 0. 이 계획이 태어난 순간 — 정직 발견

2026-07-07, 판별 리포트를 HuntPage에 붙이고 실물을 확인하던 중, 권이건이 물었다:

> *"이미 발견된 행성 말고, 우리가 직접 찾는 걸 원하는데."*

그래서 미검증 큐레이션 타깃 `KIC 10583180`("강한 신호, 정체 논쟁 중")을 라이브로 끝까지 돌렸다.
결과: 우리 4관문이 독립적으로 **UNLIKELY (2차 식 HARD 실패 → 쌍성)** 판정 → NASA KOI도 **K00748.01 FALSE POSITIVE**.
엔진은 정직했다(보정에 안 쓴 별을 광도곡선만 보고 NASA와 같은 결론).

**그러나 타깃이 정직하지 않았다.** 큐레이션 5개 타깃은 전부 이미 알려진 KOI였다:

| 타깃 | 포장된 설명 | 실제 정체 |
|------|-------------|-----------|
| KIC 11446443 | "well-studied … verify the published result" | 확정행성 (앵커) |
| KIC 9140402 | "faint star with suspected dimming" | KOI (후보) |
| KIC 10583180 | "strong signal, nature contested" | K00748.01 FALSE POSITIVE |
| KIC 7380537 | "hot Jupiter candidate range" | KOI 대응 |
| KIC 4936180 | "regular 4-5 day intervals suspected" | KOI 대응 |

"의심되는", "논쟁 중" 같은 어휘는 **알려진 천체를 미스터리처럼 포장한 연출**이었다.
이것은 PRD가 §2에서 경계한 바로 그 자기기만이다 — *"판별 없이 울타리를 열면 … 우리가 돕고 싶은 그 사람을 속이는 일."*
연출은 그 반대 방향의 같은 죄다: **판별은 정직한데 사냥터가 가짜였다.**

### 못 3 — 사냥터도 정직해야 한다

> 🌌 **"우리가 직접 찾았다"고 말하려면, 그 별이 실제로 아무도 기록하지 않은 별이어야 한다.**
> 알려진 KOI를 미확인처럼 포장해 "발견"의 느낌을 주는 것은 판별의 정직함을 배신한다.
> 진짜 단독 사냥 = **KOI 카탈로그에 항목이 아예 없는 KIC**를 훑고, 우리 판별기로 거른다.

### 정직한 기대치 — 개척지는 대부분 빈손이다

낭만을 팔지 않는다. 케플러의 밝은 별들은 NASA가 이미 샅샅이 훑었다.
KOI에 없는 별은 십중팔구 **transit 신호 자체가 없다**(그래서 아무도 안 건드렸다).
BLS는 노이즈에서도 "최우선 주기"를 뱉지만, 우리 4관문이 대부분 걸러낼 것이다.

> **개척지의 진실: 대부분 빈손, 아주 드물게 진짜.**
> 그리고 그 드문 "strong + KOI에 없음"이 나오는 순간 — 판별의 창이 그것을 신뢰 있게 만든다.
> 빈손조차 정직한 결과다: "여기엔 행성이 없다"도 과학이다.

---

## 1. 한 문장 요약

**판별기가 진짜/가짜를 가릴 수 있게 되었으니, 이제 KOI 카탈로그에 없는 별을 실제로 사냥해 —
우리 손으로 걸러낸 "신뢰도 있는 새 후보"를, 혹은 정직한 빈손을, 판별의 창과 함께 내놓는다.**

---

## 2. 현재 Hunt과의 차이 — 왜 별도 페이지인가

| | 현재 Hunt (Phase 8 + 9-A) | 9-B 진짜 사냥 |
|---|---|---|
| 타깃 | 큐레이션 5개 (전부 알려진 KOI) | KOI 항목이 **없는** KIC |
| 목적 | 판별기 **시연·교육** (알려진 답과 대조) | 실제 **개척** (답을 모름) |
| KOI 대조 의미 | "우리도 NASA처럼 찾았다" 검증 | "카탈로그에 없다" = 진짜 미기록 |
| 기대 결과 | 대부분 명확 (앵커는 strong, 위양성은 unlikely) | 대부분 빈손/노이즈, 드물게 후보 |
| 정직성 | 교육용임을 명시해야 (현재 미흡) | 빈손도 정직한 결과로 제시 |

현재 헌트 페이지는 **교육용 데모**로 정직하게 재라벨하고(§5), 진짜 사냥은 **별도 모드/페이지**로 분리한다.
둘을 섞으면 "시연"과 "발견"의 경계가 흐려져 못 3을 다시 어긴다.

## 3. 설계 스케치 (확정 아님 — 착수 시 PRD/TechSpec으로 정식화)

### 3-1. 타깃 선정 전략 (핵심 난제)

"KOI에 없는 KIC"를 어떻게 고르는가. 후보 접근:

- **(a) 무작위 케플러 KIC 샘플링** — 케플러 관측 대상 목록에서 KOI에 없는 ID를 무작위 추출. 가장 정직하지만 거의 다 빈손.
- **(b) KOI 근처 미기록 이웃** — 이미 후보가 있는 영역의 인접 별(다중 행성계 가능성). 히트율 소폭↑.
- **(c) 사용자 자유 입력** — 이미 존재(HuntPage manual KIC). 여기에 "이 별은 KOI에 없음"을 명시적으로 표시.
- **(d) 낮은 우선순위로 밀린 TCE** — NASA가 검출했으나 후보로 승격 안 한 신호. (아카이브 접근 필요, 범위 밖일 수 있음.)

> 초기 범위는 **(c) + (a)** 조합 권장: 자유 입력을 1급 시민으로 올리고,
> "무작위 사냥" 버튼으로 KOI에 없는 KIC를 하나 뽑아 돌린다.

### 3-2. 흐름

```
KIC 선택 (무작위 or 입력)
  → LC 수신 → BLS
  → 4관문 판별 (9-A 엔진 그대로)
  → KOI 대조:
       ├ 카탈로그에 있음  → "이건 이미 알려진 천체다" (사냥 대상 아님, 다음으로)
       └ 카탈로그에 없음  → 판별 trust로 분기:
              ├ strong  → ★ "우리가 찾은 신뢰 후보" (드묾, 발견기록 v2 강조)
              ├ weak    → "애매 — 추가 검토 필요"
              └ unlikely→ "빈손/노이즈/쌍성 — 여기엔 없다" (정직한 결과)
```

### 3-3. 정직성 UI 규칙 (못 3의 구현)

- 빈손을 **실패가 아니라 결과로** 제시: *"이 별에는 행성 신호가 없습니다 — 그것도 답입니다."*
- "발견" 단어는 **strong + KOI에 없음**일 때만, 그것도 "후보"로만.
- 사냥 횟수/빈손 횟수를 정직하게 노출 (예: "37번 사냥, 후보 0 — 개척은 원래 이렇다").
- 알려진 KOI가 나오면 숨기지 말고 *"이미 기록됨"*으로 정직하게 표시.

## 4. 범위 (착수 시 조정)

### ✅ 포함 (초안)
1. 진짜 사냥 전용 페이지/모드 (교육용 데모와 분리).
2. 타깃 선정: 자유 입력 승격 + "무작위 미기록 KIC" 추출.
3. 결과 분기 UI (위 3-2) + 정직성 규칙 (3-3).
4. 9-A 판별 엔진·리포트 카드 **그대로 재사용**.

### ❌ 제외 (다음 악장)
- TESS 편입 (별도 데이터 파이프라인).
- 픽셀 수준 진단 (centroid, difference imaging).
- 사용자 계정 / 발견 저장소 / 커뮤니티 (트랙 마지막 악장 9-C).
- NASA TCE 아카이브 직접 질의 (접근·범위 부담).

## 5. 선행 정리 — 현재 큐레이션 타깃 정직하게 재라벨

9-B 착수 전(또는 병행) **작은 정직 부채 청산**:
- 현재 5개 큐레이션 타깃 설명에서 미스터리 포장을 걷고, **"판별기 시연용 — 알려진 천체"**임을 명시.
- 또는 헌트 페이지 상단에 *"이 타깃들은 판별기를 배우기 위한 알려진 사례입니다"* 배너.
- 이로써 "교육 데모"와 "진짜 사냥"의 경계를 명확히.

---

## 6. 성공 기준 (초안)

- KOI에 없는 KIC를 실제로 돌려 **정직한 결과**(대부분 빈손)를 낸다.
- 빈손이 실패가 아니라 결과로 느껴진다 — 사용자가 낙담이 아니라 *"개척은 이런 거구나"* 를 배운다.
- 만약 strong+미기록이 나오면, 발견기록 v2가 판별 근거와 함께 그것을 신뢰 있게 담는다.
- 교육 데모와 진짜 사냥이 UI에서 명확히 구분된다 (못 3).
