# sub-3-6 Check — Time controls (physics dt ⊥ visual speed)

> Phase 3 — Gravity · Issue #23 · 2026-06-05

## 잘된 점

- **0.1× 가 *진짜로* 느려졌다 — 묻혀 있던 버그를 측정이 드러냈다.** 코드를 읽기
  전 가정은 "`TIME_SPEED` 상수만 `store.timeSpeed` 로 바꾸면 끝" 이었다. 그런데
  실물 루프(`clamp(ceil(δ·speed/dt), 1, …)`)는 **floor-1** 때문에 *프레임당 1 step
  미만* 을 표현하지 못해, fine-dt 프리셋에서 0.1× 가 1× 와 똑같이 굴렀다(+프레임률
  의존). sub-3-5 에 *조용히* 살아 있던 버그. sub-2-7 "측정이 가정을 이긴다" 의 또
  다른 거울 — *읽기 전 가정이 plan 을 고쳤다*.
- **정공법: 분수 누적기(fractional accumulator).** sim-time 을 프레임 간 *은행* 에
  모았다가 `FIXED_DT` 단위로 *통째* 소비. 0.1× = 여러 프레임에 한 step, 10,000× =
  한 프레임에 캡(16)까지. 게임 루프의 표준 fixed-timestep 패턴을 천체 적분에 그대로.
- **순수 코어 안 건드림.** `advanceAccumulator` 는 `lib/util/substep.ts` 의 *새* 순수
  레이어. `rk4Step`/`eulerStep` 은 한 글자도 안 고침 — *적분기 2층*(순수 코어 ↔
  렌더루프 래퍼) 원칙이 3-6 내내 지켜짐. sub-3-2 "코어 보존" 의 연장.
- **청킹 등가 테스트 = PRD §5 의 문자 그대로의 인코딩.** "12 step 을 한 프레임에 굴리든
  [5,7] / [3,3,3,3] 으로 쪼개든 *비트-동일* 한 궤도" — 즉 *프레임당 substep 수가 궤도
  모양을 못 바꾼다*. "같은 IC → 같은 궤도(시각 속도 무관)" 를 회귀로 고정. 속도가
  *언제* 찍느냐만, *무엇을* 찍느냐는 아님.
- **`paused` 가 누적도 멈춘다 → 재개 시 안 튐.** `if paused: return` 을 *누적기 갱신
  전* 에 둬서, 정지 동안 sim-time 이 쌓였다 한꺼번에 쏟아지는 lurch 를 차단. `timeSpeed`
  ⊥ `paused` 직교 설계라 Phase 2 의 `prevSpeed` 부기도 불필요 — *더 단순*.
- **재생 컨트롤 맨 앞 고정.** 섭동 슬라이더는 three-body 에서만 나타나므로, 시간
  컨트롤이 그 *뒤* 였다면 프리셋 전환마다 위치가 흔들렸을 것. 작은 레이아웃 판단이
  사용성을 지킴.

## 막혔던 점 / 트러블슈팅

### 1. "상수 치환" 인 줄 알았던 게 "아키텍처 추가" 였다 (floor-1 의 정체)
- **문제**: 0.1× 를 켜도 1× 와 체감이 같음. PRD §4-6 의 0.1×(느린 관찰)가 거짓말.
- **원인**: `Math.max(1, Math.ceil(δ·speed / dt))`. two-body 는 `dt = T/120 ≈ 0.037`,
  60fps δ ≈ 0.016 → 0.1× 든 1× 든 `δ·speed/dt < 1` 이라 *둘 다 1 로 올림*. 즉 매
  프레임 최소 1 step 강제 → 0.1× 무의미 + 프레임률 의존.
- **잘못 짚을 뻔한 가정**: "상수만 store 로 바꾸면 된다" — 코드를 안 읽었으면 그대로
  배선만 하고 0.1× 버그를 *재포장* 했을 것.
- **해결**: 분수 누적기 도입. floor-1 제거, sub-1-step/frame 을 누적으로 표현.
- **교훈**: **실물을 읽기 전엔 작업 크기를 모른다.** "간단한 치환" 이 "새 순수
  레이어 + 테스트" 로 커졌다. handoff 의 한 줄("`TIME_SPEED` → store")이 *무엇을*
  바꿀지는 말해도 *어떻게* 까지는 코드만 안다.

### 2. 부동소수 잔여 — `0.5 + 0.7 - 1 = 0.199…`
- **문제 가능성**: 누적기 잔여 테스트에서 `toBe(0.2)` 가 깨질 뻔.
- **원인**: IEEE 754 — `1.2 - 1` 이 정확히 `0.2` 가 아님(`0.19999999999999996`).
- **해결**: 잔여/0.1× 단언은 `toBeCloseTo(…, 12)`. *정수로 떨어지는* 케이스(dt=1
  스케일 비례)만 `toBe`.
- **교훈**: 분수 누적은 부동소수 동등 비교의 함정. *정수 경계* 에서만 정확 비교.

### 3. (예방) 캡 시 backlog 안 버리면 death spiral
- **문제 가능성**: 느린 프레임 → 큰 δ → 많은 substep 요청 → 더 느려짐 → 다음 프레임
  더 큰 backlog → … 악순환.
- **해결**: `rawSteps > maxSubsteps` 면 `substeps = max`, **`accumulator = 0`**
  (초과분 *드롭*, "시각 속도 = best effort"). 누적이 무한히 안 큼.
- **교훈**: fixed-timestep 루프의 고전적 함정. 캡은 *횟수* 만이 아니라 *backlog* 도 끊어야.

## 스모크에서 드러난 것 (3-6 범위 밖 — 별도 커밋)

> 시간 패널 자체는 정상(⏸/속도/적분기/readout, 60fps). 아래는 *상위 레이어*에서
> 드러난 별건. Ken 결정대로 3-6 닫고 따로 트래킹.

- **상단 `PresetSelector`(3-4) 가 사이드바 폭만큼 offset 안 됨** → 왼쪽 앱 네비 위로
  넘침. 뷰포트 전체 폭으로 깔린 레이아웃 버그. → `fix(presets)` 별도 커밋.
- **"현재 시뮬 리셋" 먹통** — 같은 프리셋 재선택 시 `presetId` 불변 → re-seed 안 됨
  (perturbation 이 이미 0 이면 아무 일 없음). TECHSPEC §3 가 예약한 `presetLoadedAt`
  nonce 미구현이 원인. → reset 커밋(nonce + ↻ 트랜스포트 버튼 + R 키, 통합 재선택
  경로 재사용)에서 해결.
- **고속(100×/10,000×)에서 trail 이 다각형으로 각짐** — *물리 아닌 샘플링* 문제.
  꼬리는 매 *프레임* 한 점 push 인데, 고속에선 한 프레임에 substep 을 최대 16 돌려
  천체가 *호 한 조각* 을 건너뜀 → 성긴 점을 직선으로 이어 원에 내접한 다각형. 궤도
  자체는 매 substep 진짜 곡선 위(정상). → 3-7 핫픽스: *frame당이 아니라 substep당*
  trail 샘플 + ring 길이 보정.

## 🌌 이번에 알게 된 우주의 한 조각

- **고정 dt 는 신뢰할 수 있는 한 장의 노출이다.** 적분의 정확도는 *시간을 얼마나
  잘게 쪼개느냐(dt)* 가 정한다 — 그건 화면이 빠르게 흐르든 느리든 *바뀌면 안 된다*.
  천체역학자가 태양계의 수십억 년을 적분할 때, *보는 사람의 조급함(시각 속도)* 과
  *우주의 진실(적분 정확도)* 을 반드시 분리한다. 빨리 보고 싶다고 dt 를 키우면 그건
  우주를 빨리 보는 게 아니라 **다른(거짓) 우주** 를 보는 것 — sub-3-5 에서 Euler 가
  깨지던 바로 그 메커니즘이다(거친 step 이 에너지를 펌프질). 누적기는 그 분리를
  코드로 박은 장치다: *"빠르게 = 같은 진실을 더 많이, 절대 더 거칠게가 아니라."*

- **그리고 dt 의 고정은 *재현 가능한 우주* 의 전제다.** figure-8 같은 카오스 민감계는
  dt 가 한 톨만 흔들려도 운명이 갈라진다. 같은 초기조건이라도 시각 속도에 따라 dt 가
  덩달아 변했다면, 0.1× 우주와 10,000× 우주가 *서로 다른 미래* 로 가버린다. dt 를
  성역으로 두는 순간, 속도는 *같은 영화를 빠르게/느리게 트는 것* 일 뿐 — 줄거리는
  하나로 고정된다. 청킹 등가 테스트가 증명한 게 바로 이 "줄거리 불변" 이다.
