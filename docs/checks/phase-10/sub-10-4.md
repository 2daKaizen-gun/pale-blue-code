## Scope

Make the frontier inviting **and** honest by moving the novelty from *space* to
*time*. A bare TIC input is expert-only and a blind random button has no context;
worse, showing confirmed planets is not a real hunt. The honest gap left to an
amateur is the **newest TESS sector** — a star present in the freshest release yet
absent from the TOI catalog. The frontier pool becomes that fresh, unrecorded sky,
presented as a browsable feed plus a first-look reveal.

Six Lights (one commit each):

- **L1 — builder v2** (`c363b1a`): `build_frontier_seeds_tess.py` auto-detects the
  newest SPOC sector (probe downward from a date estimate; empty future sectors
  return instantly), keeps only TICs absent from `toi_catalog.csv`, over-samples,
  then **selects the brightest, best-characterized stars** (a transit only shows on
  a bright star; the feed's "sun-like" line needs a real Teff). Emits schema `@2`
  (per-star identity + freshness). Regenerated from **sector 104** — all 50 seeds
  carry full identity, Tmag 4.5–8.4.
- **L2 — backend** (`aad616b`): `FrontierStar` / `FrontierPool` models; `frontier/
  random` returns the pick **enriched** (TESS) for the reveal; new **`frontier/pool`**
  feed endpoint (recency-sorted window + freshness). Graceful `@1` degrade.
- **L3 — feed** (`618abae`): `FrontierFeed` "갓 내린 하늘" — a recency-sorted card grid
  (constellation, days-since-observed, brightness, sun-likeness, light-years) above
  the picker for TESS. Shared `starCopy` helpers (strictly stellar).
- **L4 — first-look reveal** (`90bc42a`): `FirstLook` plays on every enriched pick
  (feed / TESS random / hunt-again), keyed per TIC.
- **L5 — auto-refresh** (this commit): `.github/workflows/frontier-refresh.yml` reruns
  the builder twice a month and commits **only when the pool content changed** (new
  sector or star set), never for a timestamp-only diff.
- **L6 — this Check** + the honesty reframing below.

Plus a preceding nav fix (`ab914ff`) so `/hunt` no longer stays highlighted on the

## Honesty finding + reframing (nail #3)

The live run surfaced a real tension. A **bright** unrecorded star near the southern
continuous-viewing zone (Phoenix/Tucana) has usually been observed across **many**
sectors (here: 9 sectors, a 2850-day baseline) — it is simply not a TOI. So the
naïve "this light just arrived and **nobody has looked** / you're the **first**" claim
is false for these stars. The defensible claim is narrower and true:

- **absent from the TOI catalog** (verified — nobody has *filed it as a candidate*), and
- its **newest data landed N days ago** (the freshest sector slice).

The UI copy was corrected accordingly *before* release: the feed and `FirstLook` now
say "아직 어떤 행성 카탈로그(TOI)에도 오르지 않았습니다 · 가장 최근 관측 N일 전 · 직접
판별해 당신이 처음으로 **후보에 올릴** 수 있습니다" — never "never seen." Enrichment stays
strictly stellar, so browsing still cannot leak the answer.

## Caveat (honest, deferred)

Because the bright pool is multi-sector, two things are **not** exercised here:

1. **Nail-4 `provisional`** (short-baseline downgrade) almost never fires on this
   pool — long baselines give transit counts far above `_N_MIN_TRANSITS = 5`.
2. The **detrend SG window** vs real single-sector (~27 d) TESS cadence is therefore
   still uncalibrated on live data (sub-10-3's remaining calibration item).

Both need a genuinely **single-sector** unrecorded target, which the brightness
selection filters out. This is left open on **#47** rather than claimed as done — a
future Light can add a single-sector lane (or a short-baseline live target) to
calibrate `_N_MIN_TRANSITS` and the window. Putting a calibrated number on screen
without that run would be undefendable (nail #3), so it waits.

Separately, an LC-only `strong` on an evolved giant (as above) can be a false
positive the gates cannot catch — a pre-existing Phase-9 limitation, not new here.
