## Scope

The backend that widens the real frontier hunt from Kepler to **TESS** (Phase 10,
Skyward). The pipeline already flows off a `planet_name` string (`"KIC {id}"` ↔
`"TIC {id}"`) and BLS is already mission-agnostic, so the change is a mission
*switch* — not a second pipeline. The **4-gate vetting math is untouched.**

Four Lights (issue #45):

- **Light 1 — TOI recorded gate** (`4a51f2a`): `backend/data/toi_catalog.csv`
  (8,064 TOIs) + `services/hunt.py` `toi_entries` / `is_recorded_tess` — TIC
  membership in TOI by `tid`, the TESS analog of the KOI gate (honesty nail #3).
- **Light 2 — TESS light-curve fetch** (`052f01b`): `fetch_lc_by_tic` searches
  `lk.search_lightcurve(name, mission="TESS", author="SPOC")`, caches to
  `lc_tic-{id}_tess.json`. `_build_tess_payload` records `baseline_days` and
  `sector_count` (the raw material for honesty nail 4) and stores `author="SPOC"`
  / `exptime="short"` so BLS can re-search (`author="TESS"` is invalid at MAST).
- **Light 3 — mission wiring** (`8884884`): `star_name(id, mission)` — the single
  KIC↔TIC fork; `vet(id, mission)` and every `/hunt/*` route gain `?mission=`
  (default `kepler`, backward compatible); `bls._get_full_lc` reads author/exptime
  from the LC cache meta instead of hardcoding Kepler's.
- **Light 4 — TESS seed pool** (`c2a336c`): `scripts/build_frontier_seeds_tess.py`
  queries all SPOC 2-min targets in a sector, excludes TOI `tid`s, samples N →
  `backend/data/frontier_seeds_tess.json` (50 unrecorded TICs, sectors 1–3).

Preceding docs: PRD + TechSpec (`dce79e4`), issue body (`e09d12c`).

## Seed pool build

```
python scripts/build_frontier_seeds_tess.py --n 50 --sectors 1 2 3
→ 19,055 unrecorded candidates → 50 seeds (24s)
```

Kepler's anchor-neighbour heuristic does not transfer: **TIC numbering is not sky
position**, so neighbours of a TOI are not guaranteed to have a light curve.
Instead the builder queries MAST for every SPOC 2-min-cadence target actually
observed in a sector (`Observations.query_criteria(obs_collection="TESS",
provenance_name="SPOC", dataproduct_type="timeseries", sequence_number=sector)`) —
which **guarantees a light curve exists** — then excludes any TIC present in the
TOI catalog and samples N. Pool verified: 50 TICs, unique, sorted, every entry
`is_recorded_tess == False`.

## Verification boundary (honest)

- **Verified now:** the mission switch, the TOI gate, payload construction
  (`baseline_days`/`sector_count`), cache-hit path without network, and the wire
  contract of every route under `?mission=tess` — all by pytest, plus a live MAST
  build of the seed pool.
- **Deferred to sub-10-3 (live TESS E2E):** an end-to-end fetch → BLS → vet on a
  real TIC. The detrend Savitzky–Golay window in `bls.py` assumes Kepler's 29.4-min
  cadence (`_KEPLER_CADENCE_DAYS`); TESS 2-min cadence needs the window recalibrated
  before an E2E result is trustworthy (documented in TechSpec §8). Running it now
  would produce a number we could not yet defend, so it waits for the calibration
  Light — consistent with nail #3 (don't dress up an unverified result).

## Findings

- **The pipeline was already mission-agnostic.** BLS `_find_lc_cache` iterates
  `("kepler","tess","k2")` and `_get_full_lc` re-searches from `lc_meta`, so only
  star *naming* needed a fork. Confirming this before writing code kept the 4-gate
  math (~250 lines) untouched and the diff small.
- **`author="TESS"` is the one real integration seam.** MAST rejects it; storing
  `author="SPOC"`/`exptime="short"` in the LC payload and having BLS read them back
  is what makes the cached-then-re-searched flow work for TESS.
- **KIC and TIC id-spaces can collide**, so `?mission=` is not cosmetic — a bare id
  is ambiguous. Default `kepler` keeps every Phase 8/9 caller working unchanged.
