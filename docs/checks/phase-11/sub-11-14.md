# Check: sub-11-14 — Point the pool at dwarfs (search where a small planet could actually show)

**Date:** 2026-08-11
**Branch:** main
**Verdict:** PASS (the tool was legible and honest, but it was searching the wrong stars. The
frontier pool was ranked by brightness, and bright TESS stars are giants, so only 16 of 50 were
planet-size targets — and the smallest planet any of them could reveal was ~7 Earth radii. This
sub-phase re-selects the pool for the hunt: smallest stars first. The same sector now yields 50
planet-size targets out of 50, reaching down to real M dwarfs where the floor implies an
Earth-size planet. It does not find anything — it points the search somewhere a find is possible.)

---

## The bug was the selection, not the search

`select_bright` ranked the pool by observability: brightest, best-characterized first. That was
right for the Phase-10 "fresh sky" feed — a showpiece star to come look at. It was exactly wrong
for the Phase-11 hunt. Bright TESS stars are intrinsically luminous, i.e. **large**, and a transit
depth fixes companion *radius* (`R_planet = sqrt(depth) * R_star`): the bigger the star, the bigger
a detectable dip has to be. So a brightness-ranked pool is a giant-ranked pool, and its detectable
dips are star-sized. The sub-11-5 triage measured this honestly — 34 of 50 too_big — but the
verdict was baked in at *selection* time. The hunt was searching where a planet, by construction,
could barely register.

`select_for_hunt` inverts the rank: bright ENOUGH to register a transit (`Tmag <= _TMAG_MAX`) and
characterized (a real Teff AND radius), then **smallest radius first**, brightness only as the
tiebreak. A star with no radius sinks below every measured one — it cannot be called a dwarf. The
builder's `--select` flag defaults to `hunt`; `bright` preserves the old feed order.

- **L1 — the selector** (`c02a535`): `select_for_hunt` + `--select` in
  `scripts/build_frontier_seeds_tess.py`; 6 unit tests.
- **data — the rebuilt pool** (`00952a4`): `backend/data/frontier_seeds_tess.json`, sector 104
  re-selected for the hunt.
- **observation — the first batch** (`be69415`): 10 M dwarfs fetched and searched; instrument log.

## The pool that resulted

Same sector (104), same candidate sample, different rank:

```
                    planet-size (R<=~3.18 R_sun)   R<=1.5 R_sun   smallest radii (R_sun)
bright pool  (old):   16 / 50                         4            0.96, 0.97, 1.03, ...
hunt pool    (new):   50 / 50                        50            0.15, 0.19, 0.19, 0.22, ...
```

The pool assessment confirms it: **50 plausible, 0 too_big, 0 unknown**. The smallest targets are
genuine M dwarfs (R ~0.15–0.30 R_sun, Tmag ~12–13), where the fiducial 0.40% floor implies a
minimum detectable planet of ~0.09–0.16 R_jup — **roughly 1–2 Earth radii**. The bright pool's best
was 0.60 R_jup (~7 Earth radii). The search can now, in principle, see an Earth.

## What the sky said (so far)

The 10 smallest M dwarfs, fetched and searched: **7 quiet, 2 insignificant, 1 rejected, 0
candidates.** The rejection (TIC 370142187, R=0.22) threw a significance-13.6 single event that the
edge + symmetry discriminators caught as a systematic — the third real-data proof that significance
is necessary but never sufficient. Zero candidates on the most planet-friendly stars we have
searched. That is not a failure; it is the honest texture, now measured at Earth-size sensitivity.

## Why it stays honest

- **Nothing is fetched or searched that is not stated.** 37 of the 50 dwarfs are still `not_fetched`
  — the pool grew, the *search* grows only as curves are pulled locally, and the ledger says so.
- **The selection change is transparent and reversible.** `--select bright` reproduces the old
  pool; the criteria string in the pool JSON records which selector built it. The Action's
  content-change guard still commits only when the star set actually differs.
- **The pool is bigger, not the claims.** More targets is more real sky to search, not a stronger
  statement about any of it. Every dwarf still gets the same four gates and the same honest verdict.
