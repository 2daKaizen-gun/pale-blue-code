# Check: sub-11-15 — Every dip says which gate it failed (an artifact reads as an artifact)

**Date:** 2026-08-12
**Branch:** main
**Verdict:** PASS (a real observation exposed a legibility gap in our own tool: the drilldown showed
each dip's significance and fate-colour but not *why* a dip failed, so a sub-threshold blip sitting
on a segment edge looked identical to clean noise. That gap let the sig-4.98 event on TIC 91636864
be written up in the instrument log as a wistful near-miss when it was, in fact, another edge
artifact — sub-threshold *and* shape-rejected. This sub-phase carries the failed-gate list to the
drilldown for every event, corrects the overstated log entry, and the artifact now reads as an
artifact on screen. No new physics; the gates already ran for every event — we stopped dropping the
answer.)

---

## The gap a real run exposed

The second dwarf batch (sub-11-14) turned up TIC 91636864 at significance **4.98**, a hair under the
mono floor `_SIG_MIN_MONO = 5.0`. The log called it "the closest call — the floor doing its job."
Re-reading the event honestly, that was wrong: the dip sits **0.075 d from a segment boundary**
(edge value 0.075 vs the `1.0 * duration = 0.1 d` clearance), so it **fails the edge gate** too — the
same downlink/momentum-dump signature that killed the sig-13.6 and sig-20.6 events, only quieter. It
is not a real transit 0.02 short of the line; it is a fainter edge artifact that falls short on two
independent counts.

The tool was right (it never promoted the blip). The *story* was wrong, and the story was wrong
because the drilldown couldn't show what I had to compute by hand: which gate the event failed. The
`MonotransitCurveEvent` payload carried `significant` and `passed` (all-gates) but never *which* gate.

## What changed

- **honesty (`5204c53`)** — corrected the instrument log: the sig-4.98 event is an edge artifact,
  not a near-miss; fixed both the run note and the cumulative tally.
- **backend (`3ce69f3`)** — `failed_checks: list[str]` on `MonotransitCurveEvent`, computed for
  EVERY event regardless of significance (`[ch["name"] for ch in c["checks"] if not ch["passed"]]`).
  The shape gates already run for all events; the curve builder simply stops discarding the result.
- **frontend (`dcb93a6`)** — under the curve chart, one line per dip: its significance, its one-word
  fate (후보 / 기각 / 잡음, matching the marker colour), and — for any event with a failed gate,
  insignificant ones included — the short reason (경계 / 스파이크 / 플레어 / 비대칭). Guards a stale
  response that predates the field.
- **observation (`baf5a91`)** — third dwarf batch searched (10 more), logged.

Now the drilldown shows `딥 4.98σ · 잡음 · 경계에 걸림`, and no one has to open a Python shell to see
that the quiet blip is on a segment edge.

## Why it stays honest

- **It surfaces a computed fact, it does not invent one.** The gates ran for every event already
  (`run_monotransit` line ~663); `failed_checks` is read off the same `checks`, asserted event-by-
  event against the search result in `test_curve_matches_the_searched_events_exactly`.
- **It does not weaken the significance precondition.** Below-floor events are still `insignificant`;
  the disposition order (candidate > rejected > held > insignificant) is unchanged. The failed-gate
  note is secondary information on the curve view, not a promotion path. Significance stays necessary,
  the gates stay never-sufficient.
- **It makes an artifact *more* clearly an artifact, not less.** The change works against
  romanticizing noise — the exact failure mode that produced the overstated log entry.
