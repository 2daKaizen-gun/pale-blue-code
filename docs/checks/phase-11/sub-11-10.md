# Check: sub-11-10 — When it could come round again (the earliest a second transit could appear)

**Date:** 2026-08-04
**Branch:** main
**Verdict:** PASS (sub-11-8 gave a survivor a minimum orbital period, and sub-11-9 spent it for a
maximum temperature — both describe the *orbit*. This sub-phase spends the same minimum period for
the one thing a monotransit follow-up campaign actually needs: a **date**. A single transit was
seen at epoch t0; if the true period is at least P_min, the earliest a second transit could appear

---

## Scope

A monotransit gives no period, so BLS discards it — but the survivor now carries a *minimum*
period (sub-11-8). The next transit falls at `t0 + P` for the true period `P >= P_min`, so:

```
earliest_recurrence_BTJD = t0 + P_min                          (P >= P_min: no earlier)
earliest_recurrence_JD   = earliest_recurrence_BTJD + 2457000  (TESS BTJD -> Julian Date)
earliest_recurrence_date = gregorian(earliest_recurrence_JD)   (Meeus JD -> civil calendar)
```

`t0` is in the light curve's own time frame, which for TESS SPOC products is **BTJD**
(BJD_TDB − 2457000). The Julian-Date-to-Gregorian step is the standard Meeus algorithm, exact for
a civil day.

Because the true period can only be **longer** than `P_min`, the true recurrence can only be
**later** than this date. So the honest sentence is "the transit cannot come round again before
`DATE` — the earliest edge of the follow-up window," never "the next transit is on `DATE`." Every
assumption points the same way as sub-11-8's bound: you will wait *at least* this long.

## The calendar conversion is anchored (known Julian Dates)

Three textbook Julian Dates pin the Meeus conversion:

```
JD 2451545.0  ->  2000-01-01   (J2000.0)
JD 2440587.5  ->  1970-01-01   (the Unix epoch)
JD 2457000.0  ->  2014-12-08   (the TESS BTJD reference epoch)
```

The BTJD-epoch anchor is the one this sub-phase leans on: it confirms `BTJD 0` is 2014-12-08, so a
survivor's `t0 + P_min` in BTJD lands on the right civil day. The test also checks that a
time-of-day fraction is floored to the civil day (JD 2451545.4 is still 2000-01-01).

## What the date says on a real survivor

For the best plausible target (TIC 156004112, `R_star = 0.96`, so `P_min ~= 119 d` for a 0.4-day,
1%-deep central transit), a transit at `t0 = 1500 BTJD`:

```
earliest recurrence = 1500 + 119.2 = 1619.2 BTJD = JD 2458619.2  ->  2019-05-15
```

and the date tracks both the transit shape and where in the sector it fell:

```
t0 = 1500 BTJD, T14 = 0.2 d (0.5%)  ->  P_min ~=  16 d  ->  2019-02-01
t0 = 1500 BTJD, T14 = 0.4 d (1.0%)  ->  P_min ~= 119 d  ->  2019-05-15
t0 = 1500 BTJD, T14 = 0.5 d (1.0%)  ->  P_min ~= 233 d  ->  2019-09-06
t0 = 1500 BTJD, T14 = 0.8 d (2.0%)  ->  P_min ~= 853 d  ->  2021-05-18
t0 = 1710 BTJD, T14 = 0.4 d (1.0%)  ->  P_min ~= 119 d  ->  2019-12-11
```

This is the whole point in dates: the longer the lone transit, the longer the least period it can
belong to, and the later the earliest a second transit could appear — an 0.8-day transit is
already a *years-away* recurrence window. It runs the right way, and it is exactly what a follow-up
observer needs to know before pointing a telescope: not "look on this date," but "there is no point
looking before it."

## Why it is honest

- **A bound, stated as one.** `t0 + P_min` is the *earliest* a second transit could appear; the
  true period is longer, so the real recurrence is later. The physics docstring, the copy, and the
  card all say "cannot recur before" / "아무리 일러도 … 이후" / "앞 끝," never a predicted transit
  time. The test `test_earliest_recurrence_a_longer_period_pushes_the_date_later` pins that a longer
  period bound yields a later (never earlier) date.
- **BTJD is the frame, stated where the number is.** `t0` comes from the TESS SPOC light curve,
  whose TIME column is BTJD; the offset `2457000.0` is a named constant and the copy says
  "t0는 TESS BTJD 기준." A different mission's frame would need a different offset — that caveat
  travels with the date.
- **No period, no date.** A survivor whose minimum period is `None` (no stellar radius) carries
  `earliest_recurrence = None`, and the card omits the line — the same null discipline as the
  period and temperature bounds it descends from. The tool never invents a date it cannot stand on.

## Honest boundary (carried forward)

The date is only as good as the minimum period it rests on, and it inherits every one of that
bound's caveats (the catalog radius, the main-sequence and circular/central assumptions) plus one
of its own: that `t0` is in the TESS BTJD frame. Each of them, when wrong, moves the date *later*
(a longer true period) or shifts the frame — never earlier in a way that would let the tool claim a
recurrence sooner than the physics allows. What sub-11-10 does not do is predict when the second
transit *is*, or turn a survivor into a discovery: the earliest-recurrence date is a property of
the lone transit's inferred *orbit*, not evidence that the dip is a planet. It is the one thing that
makes a monotransit *confirmable* — a human, or a follow-up campaign, now knows the earliest they
could catch it crossing again, the near edge of the window the north-star (§5–§6) names as the last
bridge from a flag to a real, confirmed world.

And still: none of the 16 plausible dwarfs is fetched yet, so no survivor with a real date exists
on the live tool today. The bound is built and tested; the sky it will describe waits on the same
single local run sub-11-7 named — `python ../scripts/fetch_plausible.py`, then watch a plausible
dwarf's first hunt. When one lands, its survivors will name not just their least period and warmest
case but the earliest they could come round again — for the first time on real starlight.
