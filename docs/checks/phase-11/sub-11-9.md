# Check: sub-11-9 — The warmest it could be (an upper bound on the world's temperature)

**Date:** 2026-08-03
**Branch:** main
**Verdict:** PASS (sub-11-8 gave a survivor a minimum orbital period — a lower bound, "at least
P_min days." That number is a floor, and this sub-phase spends it. Because P_min is the shortest
orbit the transit allows, it fixes the closest the planet could sit to its star, and the closest
orbit is the hottest. Turning P_min into an orbital distance (Kepler III, the same main-sequence
mass the period bound uses) and the star's own Teff and radius into the flux that distance
receives, a survivor can finally answer the question the whole hunt is really about: even at its
warmest, could this be a temperate world? The bound is a genuine upper limit — every assumption
pushes the number up — so the honest sentence is "at most T_eq_max," never "its temperature is.")

---

## Scope

A monotransit survivor now carries a minimum period (sub-11-8). This turns that period into the
warmest the world could be:

```
a_min    = ( G * M_star * P_min^2 / (4 pi^2) )^(1/3)     Kepler III
T_eq_max = T_eff * sqrt( R_star / (2 * a_min) )          zero-albedo, closest orbit
```

The stellar mass reuses the same main-sequence relation the period bound already stands on
(`M = rho_star * (4/3) pi R_star^3` with `rho_star = rho_sun * R^-1.75`, i.e. `M ~ R^1.25` in solar
units), so the orbital distance is consistent with the period it descends from and inherits the
same radius caveat — no second mass source invented.

**Every assumption pushes the number up, so the truth can only be lower:**

- the real period is at least `P_min`, so the real orbit is at least `a_min`, so the real
  insolation is at most this and the real equilibrium temperature is at most `T_eq_max`;
- zero albedo is the hottest a body can run — any reflection only cools it.

So `T_eq_max` is a genuine **upper bound**. The survivor earns "this world is at most T_eq_max K —
and, being probably farther out, likely cooler," never "its temperature is T_eq_max."

- **L1 — the physics** (`d7ce6ba`): `stellar_mass_kg`, `semi_major_axis_m`, and
  `max_equilibrium_temp_k` in the monotransit service, pure, no I/O.
- **L2 — join to the hunt** (`76617ea`): the pool triage index carries the effective temperature
  alongside the radius, and `hunt_monotransit` stamps every survivor with `max_eq_temp_k` from its
  own minimum period; a star with no Teff (or radius, or period bound) carries `None`. New survivor
  model field and frontend type.
- **L3 + L4 — the surface** (`203627d`): a pure, tested `survivorTempNote` reading the temperature
  as an upper bound and naming the temperate framing, and the survivor card rendering it beside the
  minimum period so the world's portrait reads in one place.

## The constant is anchored (Earth around the Sun)

Pressing Earth's orbit through the chain returns its known zero-albedo equilibrium temperature:

```
M_star(1.0 R_sun)      = 1.986e30 kg      (Msun = 1.989e30)
a(365.25 d, 1.0 R_sun) = 1.495e11 m       (1 AU = 1.496e11)
T_eq_max(365.25, 5772, 1.0) = 278.4 K     (Earth's zero-albedo value ~278 K)
```

The mass is solar to 0.2%, the distance is 1 AU to 0.1%, and the temperature lands on the textbook
zero-albedo figure. The test asserts the Earth value to +/- 2 K and the mass/distance to sub-percent.

## What the bound says on a real dwarf

For a representative K-dwarf (`R_star = 0.75`, `T_eff = 4800 K`), a single central transit implies:

```
T14 = 0.2 d  (depth 0.5%)  ->  P_min ~=  25 d   ->  T_eq_max ~= 521 K   (hot)
T14 = 0.4 d  (depth 1.0%)  ->  P_min ~= 184 d   ->  T_eq_max ~= 268 K   (temperate)
T14 = 0.5 d  (depth 1.0%)  ->  P_min ~= 359 d   ->  T_eq_max ~= 214 K   (cold)
T14 = 0.8 d  (depth 2.0%)  ->  P_min ~= 1315 d  ->  T_eq_max ~= 139 K   (cold)
```

This is the whole point in numbers, and it runs the right way: **the longer the lone transit, the
longer the least period it can belong to, and the cooler the warmest it could be.** A few-hour
transit on a K-dwarf is already a hundreds-of-days orbit whose *hottest* case is temperate — a
world worth asking about, sitting exactly on the long-period ground BLS folds away. A short, sharp
transit is a close, hot orbit; the bound says so plainly rather than flattering it.

## Why it is honest

- **An upper bound, stated as one.** The minimum period gives the closest orbit and so the hottest
  case; zero albedo makes it hotter still. Both err in the same direction, so the true temperature
  can only be lower. The physics docstring, the copy, and the card all say "at most" (많아야), never
  "is." The test `test_equilibrium_temp_is_an_upper_bound_a_longer_period_only_cools` pins that a
  longer period bound returns a lower temperature.
- **Mass from the same main-sequence relation.** The orbital distance needs a stellar mass; it
  reuses the `M ~ R^1.25` footing the period bound already stands on rather than inventing a second
  source, so the temperature is consistent with the period it descends from and carries the same
  radius caveat — a wrong radius or an evolved star moves both together.
- **No inputs, no bound.** A survivor with no effective temperature on file — even when its radius
  is known — carries `max_eq_temp_k = None`, and the card omits the line. The tool never invents a
  temperature it cannot stand on, the same null discipline as an unfetched star's size verdict.

The deliberate limits: zero albedo (a real planet reflects some light, running cooler), no
greenhouse (a thick atmosphere runs a *surface* warmer than equilibrium — but this is the
equilibrium temperature, the honest radiative figure, not a surface claim), and a main-sequence
mass. Every one of them, when wrong, tends to make the reported number an over-estimate of the
warmest case — which is the direction an upper bound wants.

## Honest boundary (carried forward)

The temperature is only as good as the radius and effective temperature it rests on, and it assumes
zero albedo, no greenhouse, a main-sequence mass, and the same circular/central orbit the period
bound does — every one of those, when wrong, tends to make the number an *over-estimate* of the
warmest case, which is the direction an upper bound wants. What sub-11-9 does not do is turn a
survivor into a discovery, or a habitable one: an equilibrium temperature is a property of the
lone transit's inferred *orbit*, not evidence that the dip is a planet, still less a temperate one.
That still rests on the significance floor and the four discriminators, and beyond them on the
follow-up (radial velocity, imaging) the tool cannot do. But the surface can now say the one thing
that makes a single transit worth a human's whole attention: this is at least an N-day world, and
at most T degrees — and when N is large and T is temperate, that is exactly the world the machines
fold away.

And still: none of the 16 plausible dwarfs is fetched yet, so no survivor with a real temperature
exists on the live tool today. The bound is built and tested; the sky it will describe waits on the
same single local run sub-11-7 named — `python ../scripts/fetch_plausible.py`, then watch a
plausible dwarf's first hunt. When one lands, its survivors will name not just their least period
but their warmest case for the first time.
