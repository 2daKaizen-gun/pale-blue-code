## Scope

This is not a new measurement — it shows the one already made. The single-transit search loads a
curve, detrends it, baselines it to 1, and finds events. The drilldown now serves *that* curve to
the browser and marks *those* events, so the reader sees the exact signal the verdict came from —
never a differently-processed picture that could tell a different story.

- **backend** (`6e6abfa`): `services/monotransit.py::monotransit_curve` — load → detrend →
  normalize (identical to `run_monotransit`), decimate to ~3000 points for the browser, and attach
  the events from `run_monotransit_cached`. New route `GET /api/monotransit/{name}/curve`
  (`MonotransitCurve` model), declared before `/{planet_name}` so the suffix resolves. 424 for an
  unfetched star. 4 tests.
- **frontend** (`c07c2a6`): `monotransitCurve` client + `MonotransitCurveChart.tsx` (a d3 scatter
  with event bands), wired into the `StarRow` drilldown as a lazy, per-star "광곡선 보기".

---

## Why it is honest by construction

- **The picture is the search's own input.** `monotransit_curve` reruns the exact preprocessing
  `run_monotransit` uses (`_get_full_lc` → `_detrend` → divide by the median), so the plotted flux
  is the flux the search scored — not a prettier or a raw one. A test pins that the events the view
  carries are the same objects the search records (`test_curve_matches_the_searched_events_exactly`:
  same `t0`, same `candidate` verdict, one-for-one).
- **Colour is fate, not loudness.** An event's marker is emerald only if it cleared every gate,
  red if it was significant but a discriminator rejected it, grey if it was a blip below the
  significance floor. The sig-74 rejection (TIC 352404492) therefore draws **red**, not green —
  the picture refuses to flatter a loud artifact, exactly as the verdict does.
- **A quiet star looks quiet.** No events means no markers: a flat curve, honestly empty. The view
  never invents a dip to have something to point at.
- **It never draws what it has not searched.** An unfetched star has no cached curve, so the
  endpoint returns 424 and the row shows no button. Same discipline as the rest of the tool:
  `not_fetched` is stated, never illustrated.

## Cost is paid only on demand

A real curve is ~10^5 samples; sending and drawing that for every row on page load would undo the
sub-11-12 speedup. So the curve loads **only when a person clicks** "광곡선 보기", per star, and the
events come from the warm memo (instant). The decimation (uniform stride to 3000 points) keeps the
shape and the gaps legible; the event bands pin each dip's location regardless of decimation. The
point count and decimation are stated on the chart, never hidden.

## Honest boundary

This makes the tool *legible*, not more *capable*. It draws the same 16-target search whose result
is still zero candidates — it just lets a person see, with their own eyes, that the one loud event
in the whole pool (sig 74 on TIC 352404492) sits on a segment edge with an asymmetric ramp, and
was right to be refused. The picture is a window into the verdict, not a new verdict. With this,
`making-the-tool-legible.md` is complete; what remains is to *use* the tool — fetch more sky as the
frontier pool refreshes, and take the honest journey to Planet Hunters — not to make it prettier.
